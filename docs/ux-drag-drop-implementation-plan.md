## 一、结论和边界

可以实现全部工具的外部文件拖入、上下独立投放、目标区域高亮，以及右侧项目文件带入。共用交互组件，但必须保留各工具不同的文件类型、输入数量和配套资料规则，不能将所有工具强行改成“上方什么都收，下方只能收文件”。

目标是新增开销小、空闲无新增轮询、拖动时不读取文件内容，不承诺绝对零 CPU/GPU 开销或所有老电脑恒定 60fps。业务计算、工作表识别、字段映射、统计日期含义、材料勾选和项目留存规则均保持原状。

## 四、用户最终会看到的拖放体验

### 1. 发现入口

- 上方整张上传卡片作为主资料目标，包括已经有文件的状态；常驻提示“可拖入 Excel、压缩包或文件夹，也可点击选择”，文字随工具规则改变。
- 下方仅“配套资料”这一整行作为独立目标，适当增加内边距形成容易投中的区域；结果位置、表单参数和生成按钮不接收文件。
- 社保下方提示“可拖入 1 个 Excel 花名册”，不能只写泛化的“拖入文件”，更不能拖到下面却加入上方。
- 全部使用“添加/选择资料”等本地处理文案，不让用户误以为拖放会上传到服务器。

### 2. 拖入、移动、移出

- 鼠标进入哪个区域，只突出哪个区域：轻微绿色底色、清晰边框和“松开后添加到社保缴费清单”或“松开后设置为参保人员花名册”。
- 已确定不支持时显示明确原因，例如“这里只接收 1 个 Excel，不支持压缩包”，不能仅靠颜色表达拒绝。
- 尚未确认的外部路径显示“松开后检查资料”，不在未做磁盘检查时声称文件已有效。
- 移出、Esc 取消、切换工具、关闭窗口和结束拖放都清理高亮；不遗留绿色状态，不依靠常驻定时器清理。

### 3. 松开后的行为

- 多输入区追加到现有列表，保持原有顺序；同一路径重复项去重，同名不同目录的文件不按文件名合并。
- 单输入区和配套区只接受一个位置；一次拖来多个则整批不采纳，说明数量限制，不偷偷取第一个。
- 有旧的单选资料时，拖入提示明确写“替换”，验证失败保留旧选择。
- 混合拖来合法和不合法对象时，整批暂不采纳，显示不支持项及原因；不静默过滤后让用户误以为全部已导入。
- 不自动解压、扫描目录树、读取 Excel、生成报表或复制大量资料；拖放完成只更新选择。开始处理时仍走现有项目留存和业务校验流程。
- 文件类型符合不等于内容符合：花名册与缴费表同为 Excel，拖到配套区只是用户指定其用途，后续仍要经过原有模板识别和字段确认。

### 4. 锁定与错误恢复

- 工具正在处理、更新下载/校验、等待重启更新、正在退出，或项目正在执行冲突性的资料写入时，不接受新的带入；前端提示和后端入口都检查。
- 异步检查期间显示轻量“正在检查所选资料”，阻止以半完成输入启动处理，但不锁死整窗。
- 每次检查绑定请求编号、工具及模式、项目和表单版本；结束时发现目标变化则丢弃过期结果，不把社保资料填进用户后来切换的工资工具。
- 连续操作有顺序；相同多选目标的追加不能因后一个请求覆盖前一个而丢失。单选更换只有最新有效请求生效。

## 五、从右侧项目文件拖入

1. 从真实文件/目录行开始拖动，超过系统拖动距离才启动；单击仍选中，双击仍打开文件，展开箭头仍负责目录展开，滚动不被当作拖动。
2. 使用独立、轻量的拖动代理；不直接移动 ListView 的 delegate，不修改列表排序，不让虚拟化回收行时丢失拖动状态。拖动开始时保存稳定路径与项目标识，不在松开时重新用旧行号取文件。
3. 投放区复用上方和下方的完整规则。内部来源携带的路径、类型和身份也要由后端验证，不盲目信任拖放数据。
4. 语义只允许“带入使用/复制选择”，不允许 MoveAction，绝不因拖放把旧结果、原件或回收站记录搬走。执行时仍走现有项目批次复制、校验和结果工作副本流程。
5. 不拖入项目根目录、回收站、内部元数据目录及聚合栏目；实际业务目录可按目标规则带入，但不在拖动途中展开扫描。
6. 第一阶段支持右侧单文件/单目录拖动，不同时扩展为整套多选文件管理器。外部多文件拖放正常支持。
7. 给右侧选中项增加一个“带入当前工具”菜单：按实际角色显示“添加为待处理资料”及“设为参保人员花名册/已有汇总表”等，不能所有工具都叫“花名册”。不适用的角色不给有效入口。
8. 保留当前右侧面板样式及折叠图标。拖动从面板向左离开后，可临时收起遮挡面板露出目标；保留用户原展开状态，完成或取消后恢复。拖动代理必须独立于面板生命周期。点击带入入口同时作为窄屏、权限限制和不便拖动时的替代方式。

Qt 5.15 已提供 [DropArea](https://doc.qt.io/archives/qt-5.15/qml-qtquick-droparea.html) 和 [Drag 的 MIME 数据及复制动作接口](https://doc.qt.io/archives/qt-5.15/qml-qtquick-drag.html)，无需为拖放升级 Qt 或引入新 UI 框架。这里是可行性依据，不等于当前 Win7 包已经通过验收。

## 六、技术落点及性能约束

### 统一接入，不复制业务规则

- `form_specs.py`：从现有 input_mode、support_mode、是否必填、当前模式生成接收策略；拆分不涉及 I/O 的类型/数量判断与后台路径验证，避免按钮、拖放、项目带入各自维护一套规则。
- 新的公共拖放目标组件：只负责区域、提示、状态及发送明确的目标角色；不每个列表项创建一套 DropArea。
- `controller.py`：统一路径转换、批量反馈、状态守卫和异步检查；所有路径通过 QUrl 的本地文件转换处理，不能字符串删除 file:// 前缀，以免破坏中文、空格、百分号、盘符和共享路径。
- `Main.qml`：接入两类目标、常驻添加/更换/清空、右侧拖动代理及带入菜单；保留现有虚拟列表和业务调用。
- 不在拖放事件中调用 `build_invocation` 或启动表头检查、OCR、解压、项目复制；松开后的选择校验与“开始处理”的完整校验分开。

### 可执行的性能底线

- 静置无新增轮询、后台扫描或循环动画；拖动反馈仅更新边框、底色和文字，不加阴影、模糊、波纹或 Shader。
- 拖动进入/移动事件只做内存层面的轻量判断；本地/共享盘的 exists、is_dir、resolve、权限检查都可能产生 I/O，应放到后台，不在鼠标每移动一次时调用。
- 一个有界的后台校验通道，不能一个文件开一个线程；整批一次通知界面，避免几百个文件导致几百次模型整体刷新。
- 保留 inputList 的 reuseItems 和 cacheBuffer=92、workspaceList 的 reuseItems 和 cacheBuffer=128；数量增加只增加必要路径数据，不增加同数量的常驻 QML 控件。
- 文件夹只作为一个输入路径加入；大目录内容在已有任务流程按需处理，资料库继续遵守只读检索约定。
- 限制提示区高度，长路径省略但可查看完整内容；提醒列表复用虚拟化，显示总条数，完整内容可按需复制，不一次拼接巨型 UI 文本。
- 对超大拖入批次分批后台校验、允许取消；网络目录失败提供原因，不承诺单个系统文件访问可以被立即打断。
- Windows 路径去重按平台规则处理，不能对 Mac 路径一律转小写；复合压缩后缀复用现有函数。

## 七、其余体验改进的安全落地方式

### 任务反馈和结果

- 沿用当前 `_queue_run_progress` 的合并更新机制，新增阶段文字，不另开轮询读日志。分阶段计数不能冒充整个任务的百分比。
- 停止按钮采用次级样式和明确文字，取消后等待已有安全退出流程，不一键强杀。
- 结果区保留“成功生成”和“需要核对”两个事实；存在提醒不等于生成失败，也不等于每条提醒对应一个人。
- 先按工具核对返回结构，第一版可准确显示“处理完成，另有 N 条提醒”。人员异常分类必须有可靠结构化依据；OCR 缓存命中信息只作运行信息，无法可靠分类的内容保留原文，不能猜测后隐藏。
- 完成后打开路径来自本次结果及项目登记，不重新递归搜索磁盘，不自动批量启动 Excel；只响应用户点击。

### 表单和错误提示

- 输入缺少和格式错误挂到对应主输入/配套输入/日期字段；清除或更换资料后及时更新错误。后端最终校验保留。
- 未打开项目时就地提供创建/打开，不清空已经选好的文件；只读项目仍保持只读，不绕过项目恢复或写入锁。
- 模板确认保留固定底栏人工核对，能明确显示“还缺哪一列”与“尚未核对”；不减少金额列、跳过文件等高风险操作的确认条件。
- 普通悬停与路径提示可以实施；不擅自调整更新弹窗颜色、侧栏位置、悬停时长及执行快捷键。

- 对同一资料、参数、映射、输入顺序，比较业务函数参数及导出内容；新增拖放入口不应改变金额、人数、日期、排序、公式及工作表内容。

## 九、明确不承诺的外部拖放来源

默认支持能提供真实本地文件地址的来源。微信、邮件或压缩软件拖出的虚拟附件若没有可用本地路径，显示“请先保存到本地后再拖入”，不自动下载、不展开虚拟文件流、不转为网页抓取。共享目录作为文件系统路径处理，但慢盘、离线、权限问题不能用界面高亮保证成功。

不同 Windows 进程权限也可能影响跨应用操作。应以普通用户启动为首选，不通过降低系统安全限制来强行放开拖放；管理员与普通权限组合列入实机验收。可参考微软关于 [UIPI 权限隔离限制](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/user-account-control-allow-uiaccess-applications-to-prompt-for-elevation-without-using-the-secure-desktop) 的说明；该说明不是本应用已复现问题的证据。
