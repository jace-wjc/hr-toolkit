## 当前处理

- 自定义 urllib HTTPS 上下文补齐 ALPN `http/1.1`，保留证书和主机名校验。
- 自动发布及手动补发工作流显式使用 `--api-transport curl`，让 API 查询、创建、更新、删除、元数据附件上传和公开校验使用 curl HTTP/1.1；不再仅在同一种 urllib 连接上重复等待。`--upload-transport urllib` 保留原小附件 multipart 编码路径，最终由所选 API 连接发送；独立大文件 curl 上传逻辑未改。
- curl 一次只发送一个请求，不启用内部自动重试；仍由同一发布逻辑进行退避及创建结果核对，不在不确定的写操作后盲目换连接重发。curl 不可用时明确失败。
- curl 禁用用户 curlrc，最低 TLS 1.2，启用正常证书验证；含令牌的 API 不跟随重定向。无令牌公开附件允许最多 5 次 HTTPS 重定向，以支持附件 CDN。URL/令牌走标准输入，正文放入任务结束即清理的私有临时目录，不写入命令行参数，不输出原始 curl 错误正文。
- API/元数据响应限制为 8 MiB，连接及总请求设有超时，外层进程超时额外保底。持续拦截、证书失败、权限不足、响应超限仍明确失败，不输出虚假的发布成功。
- Git 传输补齐 SSL 连接超时识别，沿用最多 4 次、间隔 15/30/60 秒的重试；非快进、标签冲突、鉴权等失败仍然停止，禁止强推。
- Gitee API 查询、同内容更新、删除和公开附件读取，对网页防护 HTML 403、408/429、常见 5xx、超时、连接中断及不完整 JSON 做有上限的重试。JSON 权限拒绝、证书校验失败不重试，不关闭 TLS 校验。
- 创建 Release 不直接重复 POST。响应丢失或不完整时先按 Tag 查询：已经存在则复用；确认 404 才允许再创建；查询本身失败则停止。
- 附件上传保留“先查询是否已上传成功，再决定是否重试”，源码发行版仍只维护 `SHA256SUMS.txt`，不删除维护者手工上传的安装包。
- 公开可见性轮询不再叠加已耗尽的传输重试；持续失败仍非零退出，不添加 `continue-on-error` 或跳过发布校验。
- 错误日志区分网页防护和 API 权限问题，不再输出整段防护 HTML；令牌原文及 URL 编码形式均脱敏。
