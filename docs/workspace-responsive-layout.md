# 右侧项目栏响应式布局

实施基线 `61b373d`，2026-09-15。已实现八项布局要求及后续四项布局修正；本文件随布局代码一同提交，未推送远程。下方历史 GUI 检查记录对应四项修正之前的版本，不代表修正后的交互验收。

## 交互规则

- 项目文件区从浮层 Popup 改成主 RowLayout 中的右侧组件，实际占据布局宽度；中间区域取得剩余空间，不再被项目栏覆盖。
- 收起时释放全部占位，中间区域恢复。中间面板占满剩余空间，内部内容保留原有 820px 最大阅读宽度。
- 项目栏表面宽度随可用空间变化，范围为 **320–360px**，另留 16px 间隔/边距。主窗口最小尺寸仍为 760×600。
- 展开项目栏时，为中间面板预留 **640px**。快速缩小窗口时按实时可用宽度限制项目栏占位，防止动画尚未结束时挤坏中间区域。
- 左侧固定展开（248px）时，窗口宽度 **≤1224px 自动收起，≥1304px 自动恢复**；左侧收起时，相应阈值为 976px / 1056px。80px 差值构成稳定区间，避免边界附近来回切换。
- 自动收起只改变显示状态，保留用户的展开意图；用户主动收起后，放大窗口也不会重新打开。自动收起期间，标题栏按钮提示放大后恢复，并可取消恢复。
- 展开/收起采用 **190ms OutCubic** 动画，中间区域与右栏同步分配宽度。普通连续缩放直接跟随窗口尺寸，不等待旧的 settledWidth 定时器。该定时器仅继续用于原有模态弹窗。
- 项目栏获得焦点时可用 Escape 收起。右栏不再挡住拖放目标，拖文件时保留面板，不再临时关闭再恢复。

640px 是“同时显示右栏”时的中间面板预算，并非强行增加主窗口最小宽度。760px 窗口且左菜单仍固定时，中间面板约 512px，右栏完全收起，内部内容使用更小留白并换行。

## 相关配套修改

- 标题栏按钮跟随项目栏实际位置移动；不再因逻辑 opened 状态切换而瞬间跳到另一侧。
- 项目栏的添加菜单根据按钮真实坐标定位；自动收起时关闭其子菜单。
- 中间留白按中间面板的实际宽度连续调整，替换按整个窗口宽度切换的旧留白阈值。
- 资料库选择框宽度随表单空间调整；较长勾选文字限制宽度并计算多行高度。保留原字体、色彩、按钮样式、列表模型与业务操作。
- 保留项目列表虚拟化、增量刷新、按路径选中，以及原拖放路径捕获与复制动作。未修改业务 Python、设置持久化、安装包或发布配置。

应用改动：`Main.qml`、`WindowChrome.qml`、新增 `WorkspaceSidePanel.qml`。

## 后续四项布局修正

- 主纵向滚动条保留与原 ScrollView 的联动，显示父项改为中间面板，距离面板右缘 6px；内容仍保留原有阅读宽度和边距。
- 主 RowLayout 使用完整客户区高度，只给中间面板预留 40px 标题区域。右侧项目栏恢复上下各 8px 外边距，展开时继续独立占位。
- 首次打开的首选窗口尺寸从 1400×780 调整为 1600×900；继续按当前屏幕可用尺寸限制，保留原有最小窗口尺寸。
- 考勤与周月报的设置卡片使用局部横向 Flickable，内部宽度不足 520px 时保留 520px 表单宽度并显示横向滚动条；宽度充足时隐藏滚动条、横向位置归零。卡片左右仍各留 24px，因此触发条件相当于卡片宽度小于 568px。其他页面没有横向滚动，主页面仍只纵向滚动。

本轮实际仅完成三个相关 QML 文件组件编译及两个受影响 Python 测试文件的语法编译，均通过。同步调整了既有检查的滚动条源码契约和局部横向内容边界；**未执行测试套件、GUI 探针、实机交互验收或构建**，符合项目限定的验证范围。
