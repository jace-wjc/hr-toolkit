# 外观与语言

主窗口顶部的“设置”集中提供浅色/深色和简体中文/English (US)。切换立即生效，沿用 `workspace-ui.json` 保存，默认保持浅色中文。文件选择器使用 Qt 控件，以跟随应用语言和配色，不依赖操作系统语言。

深色文件选择器使用 Qt 自带 Fusion 控件风格，并按调色板绘制导航图标，避免系统风格残留的白色按钮、滚动条和黑色箭头；切回浅色时恢复原控件风格。选择器适当增加侧栏和日期列空间，选择、取消和文件过滤规则不变。操作系统绘制的窗口标题栏仍遵循系统设置。

## 显示与业务数据边界

- `gui_qt/presentation.py` 管理偏好、Qt 原生控件调色板、Qt 自带翻译和应用翻译缓存。
- QML 统一调用 `components/Ui.qml` 的 `color()` / `text()`。共享按钮、复选框、下拉框在显示内容时翻译，原始 `text`、选项 ID 和业务模型不变。
- 文件名、路径、原表页名、列名和单元格内容保持原样。包含原表数据的下拉框设置 `translateOptions: false`，只翻译提示项。
- 业务函数、Excel 匹配键、输出文件名和输出内容不参与本地化。界面日志和“复制全部”按当前语言呈现，磁盘业务记录仍保留原文。
- 动态消息的 `{0}`、`{1}` 等参数默认原样保留。只有明确属于应用提示的参数才在 `TRANSLATED_ARGUMENTS` 中声明递归翻译。不要把员工姓名、文件路径或原表内容标记为提示参数。

## 新增主题

1. 在 `components/Palettes.js` 中增加一组完整的颜色 token，保持每个主题键集合一致。
2. 在 `presentation.py` 的 `THEMES` 注册显示名称，补充标准 Qt 控件调色板。设置列表自动读取注册项。
3. 根据新主题明暗属性调整 `Ui.dark`，供单色图标选择绘制方式；复用现有控件，不复制布局。
4. 检查普通、悬停、按下、聚焦、禁用、选中文字、弹出菜单及遮罩状态。Canvas 颜色变化必须触发重绘。

## 新增语言或文案

1. 新增与 `translations_en.py` 同结构的目录模块，以中文源文案作为键。
2. 在 `presentation.py` 中添加一个静态延迟导入函数，并注册到 `LANGUAGES`。静态导入确保 PyInstaller 能发现目录；不要仅使用动态模块名。
3. 填写显示名称及 Qt 官方语言目录后缀；没有官方目录时应补充标准控件翻译。
4. 新的界面文案使用 `Ui.text()`，不要根据语言在各个页面编写分支。含源数据的复合提示应分别处理提示文字和源值。
5. 更新记录、教程、错误和运行日志也应添加目录项。不要依赖网络翻译；未知的外部诊断内容原样保留，避免隐藏错误。

## 验证

本次验证入口：`tests.test_presentation` 和 `tests/qt_presentation_probe.py`。覆盖偏好保存、交替切换、所有工具/子模式、改名类型、设置入口点击、提示/确认/帮助/模板/原表映射/改名对话框、5,000 行虚拟预览、标准文件选择器、颜色 token 和关键对比度、CI 路由。设置 `HR_PRESENTATION_SCREENSHOTS` 可保存四种主题/语言组合及预览截图。

Qt 5 使用 `Default` 控件风格，Qt 6 使用 `Basic`；代码保持 Qt 5.15 API 和 Python 3.8 语法范围。自动化在本机 Qt 6 下运行不等同于 Windows 7 / Windows 11 实机验收，也不证明安装包的实际体积或旧设备性能。
