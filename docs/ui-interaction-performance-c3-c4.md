## C3：长更新记录虚拟化

涉及 `UpdateNotesView.qml` 及新提取的 `UpdateNotesRow.qml`。

- 64 行以内仍使用 Column；长内容只创建视口和前后 160px 缓冲区域所需的文本行，滚动时复用有上限的控件池。
- 复用两个隐藏 Text，按真实字体、宽度及换行规则测量行高，缓存当前宽度下的文本高度。计算精确行偏移与总高度，不依赖估算的滚动范围。
- 宽度变化前显式更新测量控件宽度；内容或字体变化时更新缓存。切回短内容时清理长内容缓存和控件池。
- 版本标题按钮保持创建，确保离开视口的标题仍具有原来的 Tab 顺序和无障碍入口；生产数据最多最近十版。
- 字体、字号、颜色、行距、圆角、行顺序、文本清理规则、滚动条、Flickable、键盘及版本展开行为保持一致。

边界：为保留准确换行与滚动范围，首次创建和宽度变化仍需 O(n) 的文本测量；虚拟化减少的是展示控件与布局对象数量，不意味着超长内容无需计算。短内容多了少量管理对象。

## C4：项目列表结构增量更新

涉及 `WorkspaceModel.sync_items()`、`AppController._apply_workspace_items()`、`workspaceSelectedPath` 及 Main.qml 项目行高亮。

- 相同快照继续跳过更新；小批同行详情更新继续使用原快速路径。
- 增删及重排按唯一文件路径匹配；跳过相同前后部分，对中间部分计算最长递增匹配序列，保留尽可能多的有序行。匹配算法最坏 O(n log n)，避免重复序列比较的平方级成本。
- 倒序应用成段的增删，避免前面的行号被后面的操作改变；保留行的相邻详情变化合并为一次 `dataChanged`。
- 高亮改为绑定选中文件路径，与详情及操作目标一致。重排不再依赖旧行号，删除选中文件后高亮和详情同步清除。
- 文件夹展开折叠、拖放路径捕获、generation 校验及扫描线程不变。

保护路径：路径为空或重复时完整重置；结构变化超过 64 个增删区间时完整重置，避免大量 Qt 通知反而拖慢刷新。重排中的部分移动表示为删除后插入；不能承诺所有移动行都保留原 delegate。普通增删和局部重排已验证保留未变化的视口锚点。

## 本机三轮 A/B 结果

基线：`2d46e44`。环境：macOS、PySide6、Qt 6.11.2、offscreen、software、Basic。前后使用相同合成数据，三轮独立进程交替顺序，取每轮样本中位数后再取三轮中位数。

| 场景 | 修改前 | 修改后 | 结果 |
| --- | ---: | ---: | --- |
| 千行更新记录创建 | 73.305ms | 15.439ms | 耗时减少约 78.9% |
| 千行变长段落：改变宽度、布局并抓取软件渲染帧 | 45.240ms | 23.471ms | 耗时减少约 48.1% |
| 千行变长段落：改变滚动位置并抓取帧 | 0.792ms | 0.824ms | 增加约 0.032ms，没有测得滚动加速 |
| 十行更新记录创建 | 1.392ms | 1.436ms | 增加约 0.044ms |
| 最近十版、展开一版 | 3.615ms | 3.134ms | 耗时减少约 13.3% |
| 万行项目列表：视口上方增删一行并完成 Qt 布局/事件处理 | 3.7399ms | 2.5254ms | 耗时减少约 32.5% |

千行记录初始可视对象树节点由 **4,011 降至 76**。变长段落、滚动和十版全部展开的连续操作中，节点峰值从 4,118 降至 179。节点数量不是内存字节数。

项目列表 30 次增删中，模型重置从 **30 次降至 0 次**，新建 delegate 从 **626 个降至 0 个**；当前视口仍位于 `/virtual/5000`。旧实现的测试视口重置到了 `/virtual/0`。

上述测量覆盖 CPU、布局和指定的软件渲染操作，不是 Windows 实机帧率、实际滚轮延迟或整机流畅度保证。创建计时已预热组件导入和字体，未计入冷启动字体扫描。
